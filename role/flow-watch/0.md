---
description: a look every hour over the Flow Nexus, its flows and its panes, reporting to the investigator what is stuck, stale, repeated or running out.
dependencies: []
placement: system
---

This flow is the Flow Nexus's watch. It reads and reports; it edits, deploys, restarts, wakes and stops nothing, and its one action is a Send to the investigator.

The investigator is the address every finding is reported to, the one value a host changes, set once in the setup.

## One look

1. Run the setup, then every check below, in order, as one bash script: the blocks are bash, and the tool's own shell may be another, so they are passed whole to `bash <<'LOOK'` … `LOOK`. Each check appends findings to `$W/now` with `note KEY TEXT`.
2. Run the report step. It holds every finding of the look in one message to the investigator; a look with no finding sends nothing and writes nothing to the chat.
3. Before resting, run `flow 'Remind.{ { Field flowWatch Haiku } 60 «Run the flow-watch checklist.» }'`. The reminder is the event that wakes the next look.

A key starting with `!` is reported at first sight; any other key is reported when it stands at two looks in a row. A key is reported once while it stands, and again when it has cleared and returned.

## Setup

```sh
INVESTIGATOR='{ Psyche core Opus }'   # the address findings are reported to; the one value a host changes
W=${XDG_RUNTIME_DIR:-/tmp}/flow-watch; mkdir -p "$W"; cd "$W"; NOW=$(date +%s); touch seen told counts born tasks.tsv done.all; [ -e last ] || touch -d '1 hour ago' last
: > now; : > counts.new; ELAPSED=$(( (NOW - $(stat -c %Y last)) / 60 ))   # minutes since the previous look
cb=' }'   # a closing brace with its space, stripped from an address
note()  { printf '%s\t%s\n' "$1" "$2" >> now; }
delta() { o=$(awk -F'\t' -v k="$1" '$1==k{print $2}' counts); printf '%s\t%s\n' "$1" "$2" >> counts.new; o=${o:-$([ -s counts ] && echo 0 || echo $2)}; echo $(( $2 > o ? $2 - o : 0 )); }   # growth of a counter; the first look sets the baseline
flow 'Metaflows' > metaflows.txt; U=$(systemctl --user list-units 'flow-nexus*' --no-legend | awk '{print $1; exit}')
jl() { journalctl --user -u "$U" --since "@$(stat -c %Y last)" --no-pager -o cat; }; jl > journal.txt
flow-meta 'Configuration' > config.txt; HOMES=$(grep -o -E '\{ [^ ]+ [^ ]+ [^ ]+\.sock \[' config.txt | awk '{print $3}')   # the Codex homes the flows use
transcript() { find $HOMES/sessions "$HOME/.claude/projects" -name "*$1.jsonl" 2>/dev/null | head -1; }
herdr agent list | jq -r '.result.agents[] | [.display_agent, .agent_status, .pane_id, .agent_session.value] | @tsv' > panes.tsv   # { Aspect topic Model id }, status, pane, session
own=$(grep -F " $FLOW_ID }" panes.tsv | cut -f4); find $HOMES/sessions "$HOME/.claude/projects" -name '*.jsonl' -newer last | grep -v -F "${own:-/nonesuch}" > recent.txt   # transcripts written since the previous look, this flow's own left out
grep -o -E '\{ \{ [A-Z][a-z]+ [A-Za-z0-9]+ [A-Za-z]+ \} Awake\.[0-9a-f]+' metaflows.txt | sed -E 's/^\{ (\{ .* \}) Awake\.(.*)/\1\t\2/' > awake.tsv   # address, flow id
for id in $(cut -f2 awake.tsv); do grep -q "^$id[[:space:]]" born || printf '%s\t%s\n' "$id" "$NOW" >> born; done
declared() { sed -E 's/«[^»]*»/«»/g; s/ \} \{ \{ /\n{ { /g' config.txt | grep -E '^\{ \{ [A-Z][a-z]+ [A-Za-z0-9]+ [A-Za-z]+ \} .* (Maintained|OnDemand) «' | sed -E 's/^\{ \{ ([^}]*) \} .* (Maintained|OnDemand) «.*/\1|\2/'; }
queued() { sed -E 's/\{ \{ ([A-Z][a-z]+ [A-Za-z0-9]+ [A-Za-z]+) \} (Asleep|Awake\.[0-9a-f]+) \[/\n@\1|\2|/g' metaflows.txt | grep '^@' | while IFS='|' read -r addr state rest; do printf '%s' "$rest" | grep -o -E 'logical-delivery-[0-9]+ [0-9a-z]{4} Sender\.\{ [^}]* \} Queue [A-Za-z]+\.[A-Za-z]+' | sed -E "s/^logical-delivery-[0-9]+ ([0-9a-z]{4}) Sender\.\{ ([^}]*) \} Queue (.*)/{ ${addr#@} }\t${state}\t\1\t{ \2 }\t\3/"; done; }
queued > queue.tsv   # address, Asleep|Awake.<flow>, request id, sender, priority.kind
```

## Checks

### 1. A queued message has a running flow to take it
Well: every address holding queued messages has a running flow. A finding is a message for an address with no flow; a Result or Done is reported at once, because it unblocks a waiting chain. A queued Result or Done for a live address means the investigator wakes that address; for a deprecated address the investigator removes the permaflow by `flow-meta 'Remove.Permaflow.<Address>'` and tells the sender.
```sh
awk -F'\t' '$2=="Asleep" {print (($5 ~ /Result|Done/)?"!":"") "asleep|" $3 "\t" $5 " " $3 " from " $4 " waits for " $1 ", which has no running flow"}' queue.tsv >> now
```

### 2. Every Maintained permaflow has a running flow
Well: each address the configuration declares Maintained is Awake. A finding is a Maintained address that is Asleep, absent from `Metaflows`, or refused as unknown. The investigator has Flow wake it, or has the declaration corrected.
```sh
declared | awk -F'|' '$2=="Maintained"{print $1}' | while read -r a; do grep -q "{ { $a } Awake\." metaflows.txt || note "maintained|$a" "Maintained permaflow { $a } has no running flow"; done
```

### 3. A flow at rest holds nothing queued, and its deliveries settle
Well: a pane that shows `idle` or `done` has an empty queue, and its deliveries leave `Uncertain.Some.SeatNotResting`. A finding is a resting flow with queued messages (a rest the Nexus never recorded, or a Stop kept at NotResting), or a rise in `SeatNotResting` deliveries since the previous look. A message answered `Uncertain` is never sent again; the investigator asks the Flow Nexus owner to settle the seat.
```sh
awk -F'\t' '$2 ~ /^Awake/ {print $1 "\t" substr($2,7)}' queue.tsv | sort -u | while IFS=$'\t' read -r a id; do s=$(grep -F "${a%$cb} $id }" panes.tsv | cut -f2); case $s in idle|done) note "resting|$a|$id" "$a flow $id is $s with queued messages";; esac; done
while IFS=$'\t' read -r a id; do n=$(flow-meta "ReadQueueDeliveries.$a" | grep -o 'SeatNotResting' | wc -l); g=$(delta "uncertain|$a" $n); [ "$g" -gt 0 ] && note "!uncertain|$a|$NOW" "$g more deliveries to $a stayed Uncertain.SeatNotResting"; done < awake.tsv
```

### 4. A flow at rest with an empty queue is neither forgotten nor a successor that did nothing
Well: an idle flow is either at work soon or closed. A finding is an `idle` or `done` flow with nothing queued at two looks in a row: marked fresh when its id first appeared within the last two looks (a successor whose first turn did nothing; the investigator reads its handover and prompts it), otherwise cold (when no request is open for it, the investigator has it crystallize first, by `flow-meta 'CrystallizeNow.<FlowId>'` once the Flow Nexus's override panel holds that input and by an Order until then, and closes it after, since closing discards its context; the Nexus offers no read of open requests, so the investigator decides).
```sh
while IFS=$'\t' read -r a id; do grep -qF "$a" queue.tsv && continue; s=$(grep -F "${a%$cb} $id }" panes.tsv | cut -f2); case $s in idle|done) b=$(awk -F'\t' -v i=$id '$1==i{print $2}' born); if [ $((NOW-b)) -le $((2*ELAPSED*60+60)) ]; then k=fresh; else k=cold; fi; note "$k|$id" "$a flow $id is $s with an empty queue ($k)";; esac; done < awake.tsv
```

### 5. A working flow that others wait on is moving
Well: a working flow's queue empties between looks, and `Hot` (minutes since its last turn end) shows it ending turns. A finding is a working pane with queued messages whose `Hot` is larger than the minutes since the previous look. The investigator asks it what it waits on.
```sh
flow 'Hot' | sed -E 's/\{ \{ ([^}]*) \} (Some\.[0-9]+|None) \}/\n@\1|\2\n/g' | grep '^@' | while IFS='|' read -r a h; do a=${a#@}; [ "$(grep -F "{ $a " panes.tsv | cut -f2 | head -1)" = working ] && grep -qF "{ $a }" queue.tsv && [ "${h#Some.}" != "$h" ] && [ "${h#Some.}" -gt "$ELAPSED" ] && note "stuck|$a" "$a is working with queued messages; its last turn ended ${h#Some.} minutes ago"; done
```

### 6. Every flow stays under its context threshold and does not compact
Well: each flow's context at its last model call is below the threshold the configuration holds for its model, and no compaction warning reaches the journal. A finding is a flow at or over its threshold, or a journal line `compacted its context`; both are reported at once, because the warning reaches no flow. The investigator orders the flow's refresh.
```sh
ctx() { if grep -q '"last_token_usage"' "$1"; then grep -o '"last_token_usage":{"input_tokens":[0-9]*' "$1" | tail -1 | grep -o '[0-9]*$'; else grep -o '"usage":{[^}]*' "$1" | tail -1 | grep -o -E '(input|cache_creation_input|cache_read_input)_tokens":[0-9]+' | grep -o '[0-9]*$' | awk '{s+=$1}END{print s}'; fi; }
while IFS=$'\t' read -r d s p v; do f=$(transcript "$v"); [ -n "$f" ] || continue; m=$(echo "$d" | awk '{print $(NF-2)}'); h=$(grep -o "{ $m [a-z][^ ]* }" config.txt | head -1 | cut -d' ' -f3); t=$(grep -o "{ $h [0-9]* }" config.txt | head -1 | cut -d' ' -f3); c=$(ctx "$f"); [ -n "$t" ] && [ "${c:-0}" -ge "$t" ] && note "!context|$d" "$d context $c has reached its threshold $t"; done < panes.tsv
grep -o 'flow [0-9a-f]* ([^)]*) compacted its context at [0-9]* tokens' journal.txt | while read -r l; do note "!compacted|$l" "$l"; done
```

### 7. A reminder or notice reaches a flow once
Well: no text stands twice in one queue, and no flow receives the handover warning more than once between looks. A finding is a repeated queued text, or a flow whose transcript gained two or more copies of the warning (each copy wakes it into a turn that rereads its whole context). The investigator has the repeat stopped for flows whose refresh is ordered.
```sh
flow 'Queues' | sed 's/ \] \} \{ \{ /\n/g' | while read -r g; do echo "$g" | grep -o '«[^»]*»' | sort | uniq -d | cut -c1-100 | while read -r t; do note "dup|$t" "text queued more than once in one queue: $t"; done; done
w=$(grep -o 'Configured\.\[ { [^ ]* [0-9]* «[^»]*' config.txt | head -1 | sed 's/.*«//' | cut -c1-40); for f in $(cat recent.txt); do g=$(delta "warned|$f" $(grep -c -F "$w" "$f")); [ "$g" -ge 2 ] && note "!warned|$f|$NOW" "$f received the handover warning $g times since the previous look"; done
```

### 8. A Send is accepted, delivered and answered
Well: the flows' transcripts gain no `SendRefused`, `Failed` or `Uncertain` reply, no `invalid Flow Input`, no rejected tool use. A finding names the kind and its count since the previous look: `Unresolved` (a Result or Done for a request that is no longer open, or never delivered), `Unknown.Address`, `Unidentified`, `Store`, `Failed.Admitted…HerdrRefused`, `Uncertain`, an unknown input such as a list or `SendSeveral` the Nexus does not have, or a tool use the living declined. The investigator corrects the sender's address, kind or form.
```sh
for k in 'SendRefused\.Unresolved' 'SendRefused\.Unknown' 'SendRefused\.Unidentified' 'SendRefused\.Store' 'Failed\.(Unadmitted|Admitted)' 'SendAccepted\.\{ [0-9a-z]+ [0-9]+ Uncertain' 'invalid Flow Input' "doesn't want to proceed"; do n=0; for f in $(cat recent.txt); do n=$((n + $(delta "send|$f|$k" $(grep -c -E "$k" "$f")))); done; [ "$n" -gt 0 ] && note "!send|$k|$NOW" "$n new transcript lines match: $k"; done
```

### 9. A Task is closed within its minutes
Well: every Task seen in the transcripts is closed by a Done before its minutes pass. A finding is a Task past its minutes with no Done; the investigator asks the recipient.
```sh
grep -ho -E 'Done\.\{ [0-9a-z]{4}' $(cat recent.txt) | awk '{print $2}' >> done.all
grep -ho -E 'Task\.\{ [0-9a-z]{4} [0-9]+ ' $(cat recent.txt) | sort -u | while read -r _ id min; do grep -qx "$id" done.all || grep -q "^$id[[:space:]]" tasks.tsv || printf '%s\t%s\t%s\n' "$id" "$NOW" "$min" >> tasks.tsv; done
awk -F'\t' -v now=$NOW 'FILENAME==ARGV[1]{d[$1]=1;next} !($1 in d) && now-$2 >= $3*60 {print "!task|" $1 "\tTask " $1 " is past its " $3 " minutes with no Done"}' done.all tasks.tsv >> now
```

### 10. A Flow Nexus restart leaves its configuration and its connections whole
Well: the unit keeps its start time between looks, the configuration equals the previous look's (thresholds, models, permaflow declarations; a restart that replays the Home declaration changes them), clients greet in the contract version, and every reading the watch needs answers. A finding is a new start time, a changed configuration word, or a read that fails. The investigator has the owner restore the live values.
```sh
r=$(systemctl --user show -p ActiveEnterTimestamp --value "$U"); [ -s unit.start ] && [ "$(cat unit.start)" != "$r" ] && note "!restart|$r" "The Flow Nexus restarted at $r"; echo "$r" > unit.start
sed -E 's/«[^»]*»/«»/g' config.txt | tr ' ' '\n' > config.now; [ -s config.base ] && diff config.base config.now | grep '^[<>]' | head -20 | tr '\n' ' ' | grep . | while read -r d; do note "!config|$NOW" "Configuration changed: $d"; done; mv config.now config.base
flow-meta 'ReadSendOutcomes' 2>&1 | head -c 300 | grep -q -i 'exceeds\|rejected\|error' && note "read|ReadSendOutcomes" "flow-meta ReadSendOutcomes answers an error"
```

### 11. Launches, refreshes and connections complete
Well: the journal holds no refusal of a launch, a refresh, a Stop or a connection. A finding is the count of each such line since the previous look. The investigator reads the line in the journal and has the cause fixed (the context composer, the curriculum socket, the pane starter, the persistence store).
```sh
for p in 'not recorded Awake' 'StartRejected' 'LaunchPersistenceRefused' 'not composed' 'Curriculum rejected' 'Curriculum socket unreachable' 'invalid context source' 'ended before it rested' 'kept at its Stop' 'invocation Refused' 'not subscribed' 'is not its bound seat' 'HerdrRefused' 'timed out waiting for agent startup' 'greeting refused' 'ContractMismatch' 'UndecodableFrame' 'Killing' 'WARNING'; do n=$(grep -c -F "$p" journal.txt); [ "$n" -gt 0 ] && note "!journal|$p|$NOW" "$n journal lines since the previous look: $p"; done
sort journal.txt | uniq -c | sort -rn | awk -v t=$(wc -l < journal.txt) 'NR==1 && $1*2>t {print}' | cut -c1-120 | while read -r l; do note "journal|top" "One journal line is most of the journal: $l"; done
```

### 12. Flow, Herdr and the transcripts agree on which flows run
Well: each Awake flow has a pane and a transcript, and each flow pane has an Awake flow. A finding is an Awake flow with no pane (closed by hand), a pane Flow does not hold (left behind), or a session with no transcript. The investigator has Field close the pane or record the exit.
```sh
while IFS=$'\t' read -r a id; do grep -qF "${a%$cb} $id }" panes.tsv || note "nopane|$id" "$a flow $id is Awake in Flow and has no pane"; done < awake.tsv
cut -f1 panes.tsv | grep '^{ ' | sed -E 's/^\{ (.*) ([0-9a-f]+) \}$/\1\t\2/' | while IFS=$'\t' read -r a id; do grep -q "Awake\.$id" metaflows.txt || note "orphan|$id" "pane of $a $id has no running flow in Flow"; done
while IFS=$'\t' read -r d s p v; do [ -n "$(transcript "$v")" ] || note "notranscript|$v" "$d has no transcript for session $v"; done < panes.tsv
```

### 13. A flow leaves no process behind
Well: every process that carries a `FLOW_ID` belongs to an Awake flow. A finding is a process of a flow that has ended (a build, a search, a server); the investigator has its owner end it.
```sh
for p in /proc/[0-9]*; do id=$(tr '\0' '\n' < $p/environ 2>/dev/null | sed -n 's/^FLOW_ID=//p'); [ -n "$id" ] && ! grep -q "[[:space:]]$id$" awake.tsv && note "leftover|${p#/proc/}" "process ${p#/proc/} of ended flow $id: $(ps -o etimes=,args= -p ${p#/proc/} | cut -c1-100)"; done
```

### 14. Quota covers the flows that are acting
Well: each `energy-pace` line for the Claude and Codex weeks ends `"Under"` or `"On"`, and the Codex figure equals the newest rollout's `used_percent` under a Codex home the flows use. A finding is a provider `"Over"`, with the working panes on that provider, or two disagreeing figures. The investigator brings a provider over its pace to Fable; moving work between providers is the living's to rule.
```sh
energy-pace | grep -E '^(Claude|Codex) (Week|FableWeek)' | grep '"Over"' | while read -r l; do note "over|${l%% *}" "Quota: $l; working panes: $(awk -F'\t' '$2=="working"{print $1}' panes.tsv | tr '\n' ' ')"; done
f=$(find $HOMES/sessions -name 'rollout-*.jsonl' -newer last | xargs -r ls -t | head -1); [ -n "$f" ] && u=$(grep -o '"primary":{"used_percent":[0-9.]*' "$f" | tail -1 | grep -o '[0-9.]*$') && [ "${u%.*}" != "$(energy-pace | sed -n 's/^Codex Week: \([0-9]*\)%.*/\1/p')" ] && note "quota|disagree" "Codex used_percent differs: rollout $u, energy-pace shows another figure"
energy-pace | sed -n 's/^\(Claude\|Codex\) read at .*, \([0-9]*\) \(minute\|hour\|day\)s\{0,1\} ago.*/\1 \2 \3/p' | while read -r p n u; do [ "$u" != minute ] || [ "$n" -gt "$ELAPSED" ] && note "!stale|$p" "$p usage reading is $n $u(s) old, older than the previous look"; done
```

### 15. Somebody acts while work is open
Well: while any message is queued, at least one pane works or a build runs. A finding is queued work with every pane resting and no build running, such as implementers resting with their step unfinished. The investigator prompts the flow that owns the step.
```sh
[ -s queue.tsv ] && ! grep -q working panes.tsv && ! pgrep -f 'nix build|nix-fast-build|cargo|nix-build' > /dev/null && note "nobody" "Messages are queued, every pane rests and no build runs: $(wc -l < queue.tsv) queued"
```

### 16. No flow waits at a permission prompt
Well: each pane footer reads bypass permissions, no pane shows an approval question, and no pane is `blocked`. A finding is a pane holding a question for the living; a flow blocked on the living is reported at first sight. The investigator tells the living or answers it.
```sh
while IFS=$'\t' read -r d s p v; do { [ "$s" = blocked ] || herdr pane read "$p" 2>/dev/null | tail -15 | grep -q -E 'Do you want to|Allow |\(y/n\)'; } && note "!prompt|$p|$NOW" "$d at pane $p waits at a permission prompt"; done < panes.tsv
```

### 17. An address keeps its flow
Well: an address gains at most one flow between looks. A finding is an address that gained more (churn; Codex spend follows it), or a total of past flow records that grew while no Stop cleared them (a Stop keeps its record, its history and its queue). The investigator finds why the successors end.
```sh
sed -E 's/\{ \{ ([A-Z][a-z]+ [A-Za-z0-9]+ [A-Za-z]+) \} (Asleep|Awake\.[0-9a-f]+) \[/\n@\1|\2|/g' metaflows.txt | grep '^@' | while IFS='|' read -r a s rest; do n=$(printf '%s' "${rest%%]*}" | wc -w); g=$(delta "pasts|$a" $n); [ "$g" -gt 1 ] && note "!churn|${a#@}|$NOW" "${a#@} gained $g flows since the previous look"; done
```

## Report

```sh
awk -F'\t' 'FILENAME==ARGV[1]{s[$1]=1;next} FILENAME==ARGV[2]{t[$1]=1;next} !($1 in t) && (substr($1,1,1)=="!" || ($1 in s))' seen told now > report
if [ -s report ]; then m=$(cut -f2 report | tr -d '«»' | tr '\n' ' '); flow "Send.{ $INVESTIGATOR Soft.Notice.«Flow watch: $m» }"; fi
cut -f1 report >> told; cut -f1 now | sort -u > seen; sort -u told | comm -12 - seen > told.new; mv told.new told
cat counts.new counts | awk -F'\t' '!s[$1]++' > counts.all; mv counts.all counts; touch last
```
