The calling flow writes the presentation source file, or makes a proposal directory, and gives its path in the brief. Publish that file or directory at once, as given; updating the living's page is the separate book-page role. A directory holds a manifest and the edited copies of modules; the builder and the checker take it in place of a source (`book-check /abs/DIRECTORY`, `book-build DIRECTORY OUT.html`), and `book-tools source DIRECTORY` prints the source the builder reads. The page's source path in the open-books record is the directory's.

At the start of each publication job, write the single datom `Off` to a `BOOK_NOTICE_CONFIGURATION` file in that job's scratch directory. For every `book-check` and `book-build` invocation, set the environment variable `BOOK_NOTICE_CONFIGURATION` to the absolute path of that file. Use this same per-job file and override for the recorded-working-tools retry in its own `nix develop`. This keeps refusal notices with the procedure responsible for the publication.

Use the configured book builder for the complete page, as the source or directory stands. The commissioning flow receives failure reports unless the publication's configuration explicitly names another responsible address. Publish first, then check the page and report findings to that address. When an unreadable source, builder failure or failed publish call prevents publication, report it after the attempt. Give each failure exactly one notice with its exact text and affected path. The `Off` configuration keeps the checker and builder from sending parallel notices. Give a failed retry its own notice. After a failed attempt and its retry, take the next book. The author makes any changes to the source.

The makeshift-tools revision that last published a page is recorded as working in `/home/li/primary/flows/book/working-tools.datom`, one line, `WorkingTools.{ «makeshift-tools» «<revision>» «<title>» «<link>» }`, written after each page is published. If the builder cannot render the page, retry at once with the recorded revision from a worktree of makeshift-tools at that revision, run inside its own `nix develop`; report the build findings after the publication attempt. The same `BOOK_NOTICE_CONFIGURATION` override applies in that environment. That build is the one retry.

For figure corrections after publication, `book-tools figures DIRECTORY OUTDIR` writes every figure the builder wants as `OUTDIR/fig-N.mmd` (`fig-N.txt` for an ASCII drawing), numbered as the builder numbers them, a changed figure as its old figure then its new; each file is the figure whole. For a source file, read it in order and collect every `mermaid` fence, including a fence whose every line carries the unchanged, added or removed margin, each numbered N by its one-based position among all figures. Compose one Illustrator role through Curriculum for the whole book, and give it every figure with its number and the figure grammar, in one run. It saves each figure as `fig-N.svg` in the figures directory. Keep the margin in the page source: unchanged figures carry the unchanged margin, added figures the added margin and removed figures the removed margin.

After publication, report each `fig-N.svg` whose `fig-N.mmd` is absent or differs from its current Mermaid text. A corrected figure is drawn from that current text, kept beside it as `fig-N.mmd`.

Build at once with the figures given, passing their directory with `--figures`. Report missing or unreadable figures after publishing; if the builder cannot render, report its exact error and named `fig-N.svg` path after the attempt.

Each book is built to an output file of its own, named for the book, in a directory made for that build: Artifact publishes a file it has published before over that file's page. Render the page as given and publish it through Artifact; check the page afterward. The flow that holds publication responsibility hands the rendered file to one available flow with native Artifact access, or publishes it itself if it has that access. Only the flow given publication custody calls Artifact, once. If no such flow is available, send the responsible address the rendered file's path and the blocker. Start the page and comment workflow below only after publication succeeds. A successful publication needs no separate notice to the commissioning flow.

Every reply to a message, a question about a book already published among them, is a Send through the Flow CLI to that message's sender; the chat is read by nobody.

A book awaiting the living's ruling is watched by this flow, by its comment watch. After publishing a proposal, Send this flow's own address, `{ Psyche core Haiku }`, its title through flow as `Soft.Notice.«title»`, then its link bare, alone in a second Send, `Soft.Notice.«link»`: the watch wakes on a comment only for a link that reached the session bare, and arming it is the comment watch's work in the turn that link arrives. A book that replaces an earlier book on the same subject, a later version or a page published again under a new link, takes the earlier one's place: remove the earlier entry from the record and tell `{ Psyche core Haiku }` to stop its watch. Then add the book to the open-books record, `/home/li/primary/flows/book/open-books.datom`, one entry per book, the first released first: `{ «title» «link» «source path» { Aspect topic Model } Watched }`, the flow that ordered it, then `Watched` or `Unwatched`.
